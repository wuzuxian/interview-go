# 03: 阶段二 · RAG 查询与 RAG 会话

**What to build:**
求职者选中一个或多个知识库提问，得到带 [S#] 来源编号引用的流式回答：问题先经模型改写（结合多轮历史）、按长短动态分档检索；知识库没有相关内容时给出固定拒答而非编造；回答结束后附服务端生成的参考片段列表；每次提问计数累加。并能创建 RAG 会话围绕一组知识库多轮追问：会话可置顶、改名、换绑知识库、删除；流式中断不丢已生成内容。

实现细节以 `.scratch/knowledge-base/spec.md` 的「阶段二：RAG 查询 + RAG 会话」为准。

**Blocked by:** 01（检索依赖已入库的向量）

**Status:** ready-for-agent

- [ ] 检索层：kb_id IN 过滤优先下推 SQL，前置过滤失败回退本地过滤（放大 3 倍 topK 内存过滤）；动态分档：短问题（≤4 字）topK=20/minScore=0.25、中（≤12 字）12/0.28、长 8/0.28，具体默认值对照 Java application.yml 核对；可选双路召回融合（改写路+原始路按文档 id 去重保留高分，默认关）
- [ ] 问题改写：带最近 10 条完成历史（助手回复截 200 字符），失败或关闭时降级原问题
- [ ] prompt 组装：片段编号 [S1] 来源（知识库名、原文件名、第 n/m 片段、控制字符转义）、反注入指令、用户内容数据边界包裹；三段模板（system/user/rewrite）从 Java .st 文件逐字移植
- [ ] 拒答治理：流式输出先缓冲 120 字符探测「无信息」类模板，命中立即截断为固定拒答文案，否则透传
- [ ] 收尾：流结束后追加服务端参考片段 footer；提问计数单条 SQL 批量 +1
- [ ] SSE：query 与 query/stream 均为 data-only 事件（text/event-stream），行为对齐 Java Flux 语义
- [ ] RAG 会话 7 接口：创建（kbIds 必填、标题可选）、列表（置顶优先、含消息数与知识库名）、详情（含消息）、改标题、置顶切换、换绑知识库、删除
- [ ] 会话发消息流式：先同步落库用户消息 + AI 占位；data 事件换行转义为字面 \n；完成回写全文，取消保存已生成部分（空则写固定中断文案），错误同（空则写固定错误文案）；多轮历史取最近 10 条完成消息
- [ ] 测试：HTTP 契约缝锁字段与 SSE 线协议；假上游服务缝（httptest OpenAI 兼容假 ChatModel/Embedding）锁 prompt 组装、流式行为、降级链路；动态分档与拒答探测走纯函数缝
