# Spec: 模拟面试文字主链路复刻

Status: ready-for-agent
Created: 2026-10-28
Origin: /grill-with-docs 设计访谈（共识总结 + ADR 0001/0002）
Tracker: 本地 Markdown（约定见 docs/agents/issue-tracker.md）

## Problem Statement

Java 版 interview-guide 已停用，Go 版是唯一后端，但模拟面试功能（文字主链路）缺失：求职者无法发起一场面试、逐题作答并获得评估报告。React 前端已按 Java 版契约实现且不再改动——后端缺位意味着产品核心功能不可用。

## Solution

在 Go 后端完整复刻文字模拟面试主链路：面试方向列表与 JD 解析、面试场次的创建（幂等 / 未完成复用）→ 出题（方向 / 简历 / JD 三来源，追问线性排队）→ 逐题问答（暂存 / 提交 / 提前交卷）→ Redis Stream 异步评估（分批 + 二分恢复 + 二次汇总）→ 报告 / 明细 / PDF 导出 / 删除。全部接口契约与 Java 版逐字对齐，前端零改动切换。

## User Stories

1. 作为求职者，我想查看预设面试方向列表（名称、描述、图标、分类），以便选择要练习的方向。
2. 作为求职者，我想查看某个方向的详情，以便了解它考察哪些分类。
3. 作为求职者，我想粘贴职位描述并解析出 3-7 个带优先级的考察方向，以便针对目标岗位定制面试。
4. 作为求职者，我想结合简历发起指定方向、难度与题量的模拟面试，以便获得针对我经历的提问。
5. 作为求职者，我想不传简历发起通用面试，以便做该方向的标准练习。
6. 作为求职者，我想在创建时选择 LLM 提供方（不选则用设置页默认），以便按偏好与成本选择模型。
7. 作为求职者，存在未完成场次时再次以同一简历发起面试，我想直接回到那场面试，以便继续作答而不是重新开始。
8. 作为求职者，我想显式强制开新场而忽略未完成场次，以便重新练习同一方向。
9. 作为求职者，我想逐题获取当前题目（含分类标签与是否追问），以便专注作答当前一题。
10. 作为求职者，我想提交当前题答案并自动进入下一题，以便按面试节奏完成全场。
11. 作为求职者，我想暂存当前答案而不跳题，以防页面刷新丢失输入。
12. 作为求职者，我想在答完前提前交卷，以便时间不足时仍能拿到已完成部分的评估。
13. 作为求职者，交卷后我想通过列表/详情接口轮询评估状态与失败原因，以便知道报告何时可看。
14. 作为求职者，我想查看报告：总评分与总评语、分类得分、逐题得分与反馈、优势、改进建议，以便了解自身水平。
15. 作为求职者，我想在报告中看到每题的参考答案与核心要点，以便赛后学习。
16. 作为求职者，我想查看整场问答明细（含未答题的空记录），以便完整复盘。
17. 作为求职者，我想把报告导出为 PDF，以便离线保存与分享。
18. 作为求职者，我想删除历史场次（级联删作答），以便清理不需要的记录。
19. 作为求职者，重复点击"开始面试"（携带同一幂等键）时我想只创建一场，以免产生重复数据与重复模型调用。
20. 作为求职者，同方向连续多场练习时我希望尽量不出重复知识点，以便练习覆盖面更广。
21. 作为求职者，出题模型异常时我想仍能用静态兜底题完成面试，以便功能不因模型故障不可用。
22. 作为求职者，我希望追问排在其主问题之后按顺序出现，以便有真实面试的技术递进感。
23. 作为求职者，"不知道 / 跳过"类无效回答应得 0 分并被明确指出，以便报告真实反映我的水平。
24. 作为前端开发者，我希望全部接口保持 Result 包装、lowerCamelCase 字段名与既有状态枚举值，以便零改动切换后端。
25. 作为开发者，我希望评估消费失败自动重试至多 3 次并落库最终错误信息，以便任务不静默丢失且可排查。
26. 作为开发者，我希望关键纯逻辑（分类题量分配、评估合并对齐、状态机流转、结构化输出解析兜底）有单元测试，以便重构不破坏行为。
27. 作为开发者，我希望有一条可手动执行的真实 LLM 全链路冒烟命令，以便发布前快速验证核心链路。
28. 作为运维，我希望应用不负责 interview 表的建表与迁移、且兼容库中 Java 版既有数据，以便 schema 演进由 DBA 统一管控。

## Implementation Decisions

1. **模块结构**：新增 interview 业务模块，按仓库既有约定同包分层（controller / service / repo / model 文件），内含 Skill 子系统（资源加载、方向列表、JD 解析）；路由挂现有 /api 组；响应沿用 Result 包装，业务错误用 apperr 错误码（新增 interview 段）。
2. **数据库（ADR 0001）**：interview_sessions / interview_answers 完全沿用 Java 版表结构与既有数据；GORM Entity 按 Java 列名定义；应用启动迁移不覆盖这两张表，schema 由 DBA 管理。Java 后期给其他表加的恢复/栅栏列与本模块无关（interview 表没有此类列）。
3. **LLM 编排（ADR 0002）**：直接用 eino ChatModel（JSON 响应模式）；复用现有 AI 基础模块的结构化输出器（格式指令 + 解析失败带修复提示重试 2 次 + JSON 修复）。interview 模块定义极小的 ModelResolver 接口（按 providerId 解析 ChatCompleter + 取默认 providerId），由现有 aibridge 桥实现——这是本次**唯一新增的接缝**。
4. **Prompt**：从 Java 参考实现逐字移植五组（方向题 / 简历题的 system+user、批次评估、二次汇总、JD 解析），含考官人设注入（data-boundary 包裹）、无简历通用模式附加段、防注入指令与用户数据清洗。
5. **出题**：有简历时双路 goroutine 并行（简历题 60% + 方向题 40%，简历路失败降级为全方向题）；分类题量分配算法（ALWAYS_ONE 各 1 题 → 全类目各 1 题 → 剩余按 CORE 优先轮转）；历史去重（同方向[有简历再叠加简历维度]最近 10 场、最多 60 条知识点摘要注入）；参考题库截断（单文件 3000 字、总量 12000 字）；模型失败或返回不合法（题目数量、分类 key）时裁剪或落静态兜底题。
6. **追问**：出题时随主问题一次性生成（默认 1 条、上限 2），作为独立题目线性排队，parentQuestionIndex 指向主问题——不做回答后动态追问。
7. **幂等与复用**：幂等键 DB 唯一约束兜底 + Redis SETNX 锁（等待 185s / 持有 600s）+ 结果键 TTL 1 天；有简历且未强制时复用未完成场次（Redis 映射 24h + DB 查询兜底），forceCreate 绕过。
8. **缓存与状态机**：Redis 场次缓存 TTL 24h，写路径双写缓存与 DB，读路径缓存优先 DB 兜底。状态机单向：

   ```
   CREATED ──首次取题──▶ IN_PROGRESS ──末题提交/交卷──▶ COMPLETED ──评估完成──▶ EVALUATED
   ```

9. **问答**：取题首次调用触发 CREATED→IN_PROGRESS；暂存按（场次, 题号）upsert、不推进索引；提交推进索引，末题自动交卷并入队评估；提前交卷要求未完成状态并入队评估。
10. **评估**：交卷先置 PENDING 再入队（Stream MAXLEN 1000）；消费组单消费者，跳过非 PENDING、置 PROCESSING；从 DB 重放会话与答案（评估用简历文本取自 DB 关联，不用请求参数）；分批评估（8 条/批，主问题与其追问成组不可拆）；批失败二分恢复（共享额外调用预算 6、最小组数 2，不可再拆时整段加试一次，仍失败显式降级 0 分 + 系统降级文案）；合并按 questionIndex 映射回原题，整批一致 1-based 偏移或全部非法时按位置对齐兜底；二次汇总一次调用（失败降级为批次结果拼接）；overallScore = 全部题目（含追问，未答按 0 分计入）的简单平均、全部未答时为 0，分类得分按分类平均；完成后状态 EVALUATED、逐题回填作答表。失败重试至多 3 次（重新入队），最终失败落 evaluate_error。
11. **Skill 子系统**：Java 仓库 skills/ 资源（10 个预设方向 + _shared 参考库）原样拷入并 go:embed，启动时解析 SKILL.md front matter 与 meta YAML；references 按 ref/shared 规则解析；JD 解析出的自定义方向由前端回传、临时构建、不落库（与 Java 行为一致）。
12. **配置与限流**：新增 app.interview 配置段（题量边界 3-20、追问数、批大小、恢复预算、历史去重、截断长度、结构化重试次数、限流窗口等），默认值对齐 Java application.yml；限流挂现有 Redis 固定窗口中间件（创建场次 全局 5/IP 5、提交答案 全局 10、JD 解析 IP 5；精确窗口值实现时以 Java 注解为准）。
13. **PDF 导出**：复用现有 PDF 导出基础设施（已解决中文字体），章节结构对齐 Java 报告：总评分与总评语、分类得分、逐题问答与反馈、参考答案与要点；版式不逐像素复刻。
14. **级联删除**：删除简历级联删除其面试场次与作答，沿用现有简历模块行为。
15. **API 契约**：15 个端点（12 会话 + 3 Skill）与 Java 逐字对齐——字段名 lowerCamelCase、枚举值（CREATED/IN_PROGRESS/COMPLETED/EVALUATED；PENDING/PROCESSING/COMPLETED/FAILED）、Result 包装、HTTP 200 + 业务码语义。

## Testing Decisions

- **好测试的标准**：只测外部行为——给定输入与脚本化的模型响应，断言输出与状态；不 mock 内部步骤、不断言实现细节。
- **接缝**：唯一新增接缝是 ModelResolver。测试注入 stub ChatCompleter，按调用次序返回脚本化 LLM 响应，可注入格式错误响应以覆盖修复重试与兜底路径。
- **纯函数表驱动测试**（先例：resume 模块的 suggestion 测试风格，同包 `_test.go`、中文注释说明契约动机）：分类题量分配、评估结果合并与偏移对齐、题目数量/分类校验与兜底裁剪、状态机流转合法性。
- **真实 LLM 冒烟**：提供手动执行的冒烟命令，走真实 Provider 完成 创建→出题→模拟作答→交卷→轮询评估→报告→PDF 导出，作为发布前人工验收项。
- **不做**：DB / HTTP 层自动化集成测试（仓库无此先例，且 DB 依赖 Postgres 实例）。

## Out of Scope

- 语音面试（WebSocket、实时 ASR/TTS、INTRO/TECH/PROJECT/HR 分阶段流程、上下文压缩）
- 知识库模块及知识库面试入口（题库抽取、knowledge_base_questions 表）
- interview 表的建表与迁移（DBA 负责；全新环境需先手工建表）
- 鉴权（仓库现状即全接口匿名）
- RAG / 向量检索出题（出题为静态参考注入，非检索）
- 前端任何改动

## 与 Java 行为的有意偏离（实现完成后的完整清单）

除“逐字对齐 Java”外，以下偏离是经过裁决的有意行为，回退任何一条前请先读对应理由：

1. **questionCount 在 Go 侧真正校验**（3-20）：Java 创建端点漏了 @Valid，校验形同虚设；spec 明确要求校验。
2. **report 对已评估场次直接返回存量报告**：Java 每次 GET /report 都重调 LLM 并覆盖旧报告；Go 仅 COMPLETED（未评估）走同步兜底评估，避免重复模型调用与报告被覆盖。
3. **导出失败用 Result 包装**（HTTP 200 + 业务码）：Java 返回 HTTP 500 空 body，与仓库统一响应约定不符。
4. **评估全批失败上抛走重试**（0 批产出逐题评估时返回 error → 消费者重试 3 次 → FAILED + evaluate_error）：Java 会落全零报告并置 EVALUATED，使重试机制失效——正是 docs/经验-AI调用超时与异步任务兜底.md 警告的“失败固化为成功”；部分成功仍按 Java 逐批降级，两种降级文案逐字保留。
5. **出题全失败回退静态兜底题**（不报错）：Java 在单/双路全失败时上抛 BusinessException，但 spec 用户故事 21 明确要求“功能不因模型故障不可用”；Provider 解析错误（未知 provider）仍透传业务错误。双路内部降级（简历路失败→全方向题）与 Java 逐字一致。
6. **同步报告保存失败上抛 error**：Java 为 warn-only；按经验文档教训，保存失败不应固化为成功（客户端可重试）。
7. **限流窗口用固定窗口近似** Java 滑动窗口：额度与端点逐字一致（创建 全局5/IP5、提交 10、parse-jd IP5，均每秒），仅窗口算法有别，未引入新限流组件。
8. **评估恢复调度器（ZSET 在队时间戳 + 阈值补投）语义强于 Java**：interview 表无恢复列（ADR 0001），Java 仅 PEL 认领；Go 额外补投停滞任务，去重靠 shouldSkip 守卫。
9. **PDF 标题用“模拟面试报告”**（Java 原文）**并新增“分类得分”节**（票面验收要求，Java 无此节）；问答详情补要点与追问标记；无页眉页脚、书签树保留。
10. **答案提交不校验顺序**（可跳题）、**DELETE 不幂等不清缓存**、**shouldSkip 守卫**、**resumeId 复用静默返回旧场次**：均照抄 Java 逐字行为（包括其怪癖），未做“改良”。
11. **实现级细节**：锁轮询 100ms（Java Redisson 默认 1.5s）、缓存写失败不阻断创建（读路径 DB 兜底）、categoryScores 按分类名稳定排序（Java HashMap 无序）、answered_at 更新时刷新（Java 仅首次写入）、questionIndex 缺失返回 400（Java NPE→500）。
